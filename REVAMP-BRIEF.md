## 1. Identity, from scratch (tastemaker drives this)

Before writing a single line of UI, **invoke the `tastemaker` skill** and run its full flow for this project:

- Generate a per-project **palette** with a verified contrast contract, a **type system**, and a **reference board**, all anchored to the subject: real-time computer vision, edge hardware, industrial deployment, a person who ships. Reach for references from that world (instrumentation, machine vision, oscilloscopes, CAD, terminal, sensor HUDs, industrial control), not generic SaaS.
- Produce tastemaker's **numbered anti-slop gate list** and commit to it. Everything you build is checked against it at the end.
- Deliberately avoid the current stack's defaults so the result is a genuine reset: do not reuse the exact brass `#D2A24C` + `#0B0D12` palette or the Chivo / Libre Franklin / Martian Mono trio unless tastemaker independently re-derives one of them as the strongest choice and you can defend it.

Then **formalize the identity into tokens** so it is systematic, not vibes:

- `color-system` (ui-design) for the tonal scales and semantic roles; `dark-mode-design` and `theming-system` for a first-class light AND dark theme (both must be excellent, not one inverted into the other). Preserve the existing no-flash theme mechanism (`components/theme-script.tsx`, `data-theme` on `<html>`, nav toggle) and re-skin it.
- `typography-scale` + `readable-measure` for the type scale and line lengths. Choose fonts that are free, self-hostable or via `next/font`, and distinctive (avoid Inter / JetBrains Mono / Clash Display, the template tell). Load them `display: "optional"` to protect against CLS (font swap re-wrapping the hero was the entire prior mobile CLS).
- `spacing-system` + `layout-grid` for the spatial system and responsive grid.
- `motion-system` for duration/easing tokens and reduced-motion policy.
- Map all of it into `app/globals.css` `@theme` tokens. Keep one reserved-action-color discipline if tastemaker's palette supports it (it is a strong conversion mechanic), but that is now tastemaker's call, not a given.

Write the resulting identity decisions to a short `DESIGN.md` so they are legible and enforceable.

## 2. The signature (open competition)

A great CV-engineer portfolio has one memorable thing. The current site's is a live-detection HUD over my photo (boxes, scan line, FPS/latency/confidence that react to the cursor). **It is the incumbent, not the winner.**

- Brainstorm 3 to 4 distinct signature concepts that dramatize "computer vision that runs in production" (examples to push past, not copy: a segmentation/pose/keypoint reveal on the portrait; a depth or optical-flow field; an edge-device telemetry panel; a training-to-inference timeline; a real webcam demo running a tiny in-browser model). Judge each on: is it unmistakably CV, is it unique to me, does it stay fast, does it degrade gracefully with reduced-motion and without JS.
- Use `apple-design` and `find-animation-opportunities` to shape the interaction and motion of the candidates. Pick the strongest. Rebuild it properly; do not port the old component.
- Constraint: the signature is an enhancement layer. The `<h1>` (the LCP element) and all copy must render on first paint without waiting on it, and it must pause when off-screen.

## 3. Structure, hierarchy, and conversion

Re-derive the page composition (do not assume the current section order is right). Sections to cover, ordered for a 15-second read that moves a high-intent visitor to contact: hero, a trust/proof strip, Selected Work (CV first), Capabilities, About (with the real photo), Contact, footer. A persistent primary CTA (sticky nav on desktop, thumb-reachable on mobile).

Apply the interaction-design laws as design tools, not decoration:

- `visual-hierarchy` (and `critique-visual-hierarchy` to check) so the eye lands on the value prop then the CTA.
- `hicks-law` and `millers-law` to keep choices and groups small; `serial-position-effect` and `von-restorff-effect` for ordering and making the one CTA dominate.
- `fitts-law` for control sizing and the mobile CTA; `jakobs-law` for the patterns that should stay familiar.
- `peak-end-rule` for the hero moment and the contact close; `aesthetic-usability` and `interfaces-that-feel` so it lands warm, not clinical.
- Selected Work: `data-visualization` thinking for the metric callouts; keep the CV projects that lack screenshots rendering their real pipeline (the current `Schematic` idea is fine to reimagine).

## 5. Motion pass

Motion is one orchestrated hero moment plus restrained, consistent scroll and state transitions. Use `animate` to implement, `apple-design` for the physicality (springs, interruptibility, momentum where it fits), and `motion-system` tokens for consistency. Then run `improve-animations` across the result and apply its plan. Every animation respects `prefers-reduced-motion`: the signature settles to a static frame, reveals resolve to their final state, nothing loops. Scattered, showy motion reads as AI-generated; when unsure, do less.

## 7. Quality and acceptance criteria (hard gates)

Verify in a real browser (drive it, screenshot it, do not assume):

- **Lighthouse** against `npm start` (production build), both mobile and desktop presets: performance, accessibility, best-practices, SEO all **>= 95, target 100**. **CLS 0** (or < 0.01). Mobile LCP as low as you can get it (the LCP node should paint without waiting on JS or webfonts).
- **Accessibility:** WCAG AA contrast in both themes, verified by computing ratios, not by eye. Visible keyboard focus on every interactive element. Full keyboard operability. Correct semantics and labels.
- **Responsive:** flawless from 360px up, no horizontal overflow at any width, real tap targets on mobile.
- **SEO:** title, meta, Open Graph image, sitemap, robots, JSON-LD Person schema, all updated to the new identity and the CV positioning.
- **Build:** `npx tsc --noEmit` clean, `npx next build` clean and fully static.
- **No em dashes anywhere.**
- **Honesty:** no invented metrics or testimonials; `TODO`s preserved where real numbers are missing.

Do not regress the current scores (desktop was 100/100/100/100, mobile 95/100/100/100, CLS 0). Beat them or match them with a better-looking site.
